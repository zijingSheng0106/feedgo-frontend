# 三、S 级真题：必须脱稿回答

## 1. 请介绍项目，并说一个真正的难点 `[S3][S4][S5][S12]`

### 我的回答

我做的是一个 Go + Vue 3 的短视频 Feed 系统。前端使用 TypeScript、Pinia、Vue Router 和 Vite，后端使用 Go、Gin、MySQL、Redis 与 RabbitMQ。前端覆盖推荐流、点赞榜、关注流、发布、评论、私信和 SSE 通知。

我重点讲分片上传，因为它不是简单选择文件后一次 POST。前端先计算整文件 MD5，按 5 MiB 切片，向服务端初始化会话；服务端返回已经存在的分片编号，前端只构造缺失分片列表，使用三路并发上传，每片最多重试三次，最后请求服务端合并。这样单片失败只重传一片，重新选择同一文件还能根据服务端状态续传。

难点主要有三类：第一是并发调度，必须确保同时运行数不超过三且最终只 resolve 一次；第二是进度计算，最后一片可能不足 5 MiB；第三是恢复语义，缺哪些片必须由服务端确认，不能只相信浏览器本地状态。

如果追问不足，我会主动说明：当前重试是立即重试，生产环境应增加指数退避和抖动；MD5 用于完整性而不是密码安全；还可以使用 Web Worker 计算大文件哈希，减少主线程占用。

## 2. Vue 2 和 Vue 3 有什么核心区别？`[S1][S4][S6][S12]`

### 我的回答

我主要使用 Vue 3。对业务开发影响最大的变化有四点。

第一，Vue 3 提供 Composition API，可以把同一业务关注点的状态、计算和方法放在一起，再提取成 composable。我的 Feed、播放器、点赞关注分别拆成 `useVideoFeed`、`useVideoPlayer` 和 `useLikeFollow`。

第二，响应式底层主要使用 Proxy，可以拦截对象属性新增、删除等操作；Vue 2 主要使用 `Object.defineProperty` 逐个劫持已有属性，对新增属性和数组操作需要额外处理。

第三，Vue 3 对 TypeScript 和 Tree Shaking 更友好，`createApp` 也让应用实例隔离更清楚。

第四，Vue 3 在编译和虚拟 DOM 更新上做了优化，例如静态提升和 patch flag，可以让运行时更聚焦真正动态的部分。

我不会说 Vue 3 在任何场景都绝对更快。历史项目迁移还有生态、兼容性和成本问题。

## 3. Vue 3 响应式是怎么实现的？`[S1][S2][S5][S8][S9]`

### 我的回答

概念上是“读取时收集依赖，修改时触发依赖”。Vue 3 对 reactive 对象使用 Proxy：组件渲染或 computed 执行期间读取属性时，当前 effect 与属性建立关系；属性被 set 后，Vue 找到相关 effect 并调度重新执行。

`ref` 对基本类型通过带 getter/setter 的 value 包装实现；如果 ref 包含对象，内部也会转换成响应式对象。模板会自动解包 ref，所以模板写 `loading`，脚本中写 `loading.value`。

```ts
const loading = ref(false)
const form = reactive({ title: '', description: '' })
```

我在回答时会区分“响应式”与“数据双向绑定”：响应式是状态改变驱动视图更新；输入框的 `v-model` 才进一步把视图输入写回状态。

## 4. computed 和 watch 有什么区别？`[S2][S12]`

### 我的回答

computed 用于纯粹的派生值，具有缓存；依赖不变，多次读取不会重新计算。watch 用于状态变化后执行副作用，例如请求、播放器控制、写存储或释放资源。

```ts
const canSubmit = computed(() =>
  form.title.trim() !== '' && !loading.value
)
```

文件变化后创建预览 URL 会调用浏览器 API，因此使用 watch，并在替换前撤销旧 URL：

```ts
watch(() => publishForm.video, file => setPreviewVideo(file))
```

能用 computed 表达的派生状态不应该再用 watch 手动同步，否则会出现两个状态源和漏更新。

## 5. Vue 生命周期怎么用？为什么请求常放在 mounted？`[S1][S12]`

### 我的回答

`onMounted` 在组件 DOM 第一次创建并插入页面后执行，适合首次加载、访问模板 ref、初始化播放器和注册浏览器事件。`onUnmounted` 或 `onBeforeUnmount` 用来释放对应资源。

我的首页在 mounted 后加载 Feed、等待 nextTick 让 video DOM 生成、播放当前视频并注册键盘事件；卸载时移除键盘事件。发布页卸载时撤销 Object URL；AppShell 卸载时关闭 EventSource。

请求不依赖 DOM 时也可以在 setup 中启动，并不是所有请求都必须等 mounted。关键是明确生命周期和清理责任。

## 6. ref 和 reactive 有什么区别？`[S1][S9]`

### 我的回答

ref 可以包装任意类型，脚本通过 `.value` 访问，适合单个值和需要整体替换的数据；reactive 主要包装对象，直接修改属性，适合表单等成组状态。

```ts
const video = ref<Video | null>(null)
const form = reactive({ title: '', description: '' })
```

解构 reactive 对象的普通属性可能丢失响应式连接，需要使用 `toRefs`，或者不直接解构。DOM 模板 ref 也常用 `ref<HTMLDivElement | null>(null)`，因为 setup 执行时 DOM 还不存在。

## 7. 组件有哪些通信方式？`[S1][S4][S7]`

### 我的回答

父传子使用 props，子通知父使用 emits；父组件需要调用子组件暴露的方法时可以使用模板 ref 和 `defineExpose`；跨多层但范围明确可以使用 provide/inject；跨页面共享业务状态使用 Pinia；内容结构复用使用 slot。

我不会把 EventBus 当默认方案，因为事件来源和清理关系不直观，项目变大后难追踪。通知列表和未读角标由不同组件使用，因此放 Pinia；评论抽屉的开关和当前视频只属于首页，留在父组件并通过 props/emits 与子组件通信。

## 8. 为什么使用 Pinia？Pinia 刷新后数据会不会丢？`[S4][S6][S7][S12]`

### 我的回答

Pinia 管理多个不相邻组件共同使用的响应式状态。我的 AppShell 管理通知连接，通知页展示列表，导航显示未读角标，它们需要共享同一份状态，所以 EventSource 管理逻辑、items 和 unreadCount 放进通知 Store。

Pinia 状态默认存在 JavaScript 内存中，刷新页面会重新创建。需要持久化的登录 Token，我显式写入 localStorage，并在 Store 初始化时读取；通知列表不必长期本地持久化，因为数据库才是可靠来源，刷新后重新请求。

持久化不是越多越好。把过期业务数据全部保存到本地容易产生脏数据；敏感 Token 放 localStorage 还有 XSS 风险，生产环境更适合 HttpOnly Cookie 等方案。

## 9. hash 路由和 history 路由有什么区别？`[S3][S12]`

### 我的回答

hash 模式 URL 带 `#`，井号后内容不会作为普通路径发送给服务器，部署简单但 URL 不够自然。history 模式使用 History API，URL 更正常，但直接刷新 `/video/1` 时服务器必须回退到 `index.html`，否则会按真实路径查文件并返回 404。

我的项目使用 `createWebHistory()`，Nginx 配置：

```nginx
try_files $uri $uri/ /index.html;
```

浏览器拿到入口 HTML 后，再由 Vue Router 根据当前 URL 渲染对应组件。

## 10. Vite 为什么开发启动快？开发和生产有什么区别？`[S3][S4][S6][S7][S12]`

### 我的回答

开发阶段，Vite 利用浏览器原生 ESM 按需提供源模块，不需要每次启动先把所有业务代码完整打成一个 bundle；依赖会预构建，HMR 更新也能沿模块边界快速传播。

生产阶段仍要执行构建、Tree Shaking、压缩、代码拆分和资源哈希，输出 HTML、JS、CSS 静态文件。我的项目先由 `vue-tsc -b` 做类型检查，再运行 Vite build，最终 dist 被复制进 Nginx 容器。

“开发阶段不打包”是一种简化说法，不代表完全没有转换。`.vue`、TypeScript 和依赖仍需要插件转换与预处理。

## 11. JavaScript 事件循环怎么执行？`[S3][S4][S6][S7]`

### 我的回答

同步代码先进入调用栈执行。当前任务结束、调用栈清空后，事件循环会先清空微任务队列，再让浏览器获得渲染机会并进入后续宏任务。

Promise 回调和 await 后续通常是微任务，setTimeout 是宏任务。因此：

```ts
console.log('A')
setTimeout(() => console.log('B'), 0)
Promise.resolve().then(() => console.log('C'))
console.log('D')
```

常见顺序是 A、D、C、B。`setTimeout(..., 0)` 不是立即执行，只是最早在后续宏任务阶段有机会执行。

## 12. Promise.all 中一个失败，其他请求会停止吗？`[S3]`

### 我的回答

`Promise.all` 返回的 Promise 会在任一输入 reject 后立即 reject，但已经启动的其他异步任务默认不会自动取消，它们仍可能继续运行。Promise 本身没有通用的强制取消能力；fetch 需要 AbortController。

我的通知加载同时请求列表和未读数，任何一个失败都视为这次整体同步失败。如果业务允许部分结果，可以使用 `Promise.allSettled`；如果需要失败后取消其他 fetch，应把同一个 AbortSignal 传给相关请求。

## 13. 浏览器输入 URL 到页面显示发生了什么？`[S3][S11]`

### 我的回答

浏览器解析 URL，检查缓存，进行 DNS 解析，建立 TCP 连接；HTTPS 还要进行 TLS 握手。随后发送 HTTP 请求，服务器或 CDN 返回 HTML。浏览器解析 HTML 创建 DOM，解析 CSS 创建 CSSOM，合成渲染树，进行布局、绘制和图层合成；遇到 JS 还要按加载方式下载和执行。

我的部署中，Nginx 返回 Vue 静态文件，把 `/api` 反向代理给 Go 后端。JavaScript 加载后创建 Vue 应用、安装 Pinia 和 Router，再挂载到 `#app`。业务数据随后通过 API 获取。

## 14. 什么是跨域？你项目怎么解决？`[S2][S5][S6]`

### 我的回答

协议、域名和端口中任一不同就可能构成不同源。浏览器同源策略限制脚本读取跨源响应，某些请求还会先发 OPTIONS 预检。服务端可用 CORS 响应头明确允许来源、方法和请求头。

我的开发环境可以由 Vite 把 `/api` 代理到 Go 后端，生产由 Nginx 同源反向代理，因此浏览器始终请求当前站点的 `/api`。这减少了跨域配置，但后端仍要做鉴权。CORS 是浏览器策略，不等于接口权限控制。

## 15. Cookie、localStorage、sessionStorage 有什么区别？`[S3][S6][S7][S11]`

### 我的回答

Cookie 会按域和路径规则自动随请求发送，可设置 HttpOnly、Secure、SameSite；localStorage 持久存在且 JavaScript 可读；sessionStorage 只属于当前标签页会话。

我的项目当前把 Access/Refresh Token 放 localStorage，便于刷新恢复，但存在 XSS 窃取风险。生产方案会考虑把 Refresh Token 放 HttpOnly + Secure + SameSite Cookie，Access Token 短期放内存，并增加 CSRF 与 CSP 防护。

localStorage 没有原生过期机制。如果确实要一个月过期，要同时保存过期时间，读取时检查并删除；但 Token 是否有效最终仍应由后端判断。

# 四、A 级真题：与项目强相关的深入追问

## 16. SSE 和 WebSocket 怎么选？断线怎么办？`[S6][S8][S9]`

### 我的回答

SSE 是服务端到客户端的单向文本流，基于 HTTP，EventSource 原生支持自动重连；WebSocket 是全双工，适合高频双向聊天和协作。通知只需服务器推向浏览器，因此我选择 SSE。

我的通知先落数据库，再调用 SSEHub 推送。实时消息漏掉时，重新请求通知列表和未读数可以从数据库恢复，并按通知 ID 去重。当前还可以改进为重连成功后自动 load，或者让服务端发送事件 id 并支持 Last-Event-ID 补发。

Nginx 对 SSE 需要关闭代理缓冲并提高读取超时，否则消息可能被积攒后才送到浏览器。

## 17. 如果服务器 100 毫秒推送 1000 次，页面卡顿怎么办？`[S6][S8]`

### 我的回答

瓶颈通常不是网络接收本身，而是每个小片段都更新响应式状态、解析 Markdown、触发布局和渲染。我会把收到的数据先追加到非响应式缓冲区，用 requestAnimationFrame 或几十毫秒批量提交一次 UI；Markdown 解析也按段或增量处理，而不是每个字符全量重算。

如果是大模型打字机效果，还可以让网络接收速度与展示速度解耦：接收队列保证不丢数据，展示定时器按固定批量消费；队列积压过大时动态增加每批字符数。组件卸载时取消 RAF、定时器和请求。

我的通知频率低，目前不需要这种批处理；但同样的 SSE 技术用于高频流式文本时必须考虑背压。

## 18. 连续发送多个请求，怎么保证只使用最新结果？`[S3]`

### 我的回答

我会使用 AbortController 或请求版本号。搜索词变化时先 abort 上一个 fetch；或者给每次请求生成递增 requestId，返回时只有 ID 等于当前最新 ID 才写状态。

```ts
const requestId = ++latestRequestId
const result = await search(keyword)
if (requestId !== latestRequestId) return
items.value = result.items
```

我的 Feed 已按 Tab 隔离状态并防止同一 Tab 重复加载，但还没有为所有接口增加取消和版本校验，这是明确改进项。

## 19. 浏览器缓存怎么工作？`[S3][S4][S6]`

### 我的回答

强缓存通过 Cache-Control/Expires，让资源在有效期内直接使用本地副本；协商缓存通过 ETag/If-None-Match 或 Last-Modified/If-Modified-Since，请服务器判断是否变化，未变化返回 304。

`no-cache` 不是完全不缓存，而是使用前要重新验证；`no-store` 才是不要存储。`max-age=0` 表示立即过期，通常需要协商验证。

Vite 构建出的带内容哈希 JS/CSS 适合长期强缓存，因为内容变了文件名也变；`index.html` 应短缓存或协商缓存，避免继续引用旧哈希资源。SSE 则应该禁用缓存。

## 20. script 的 async 和 defer 有什么区别？`[S6][S8]`

### 我的回答

普通 script 可能阻塞 HTML 解析。async 和 defer 都可以并行下载脚本，但 async 下载完成就执行，多个脚本执行顺序不保证；defer 等 HTML 解析完成后按文档顺序执行，通常在 DOMContentLoaded 前。

模块脚本默认具有类似 defer 的行为。现代 Vite 项目入口一般使用 `<script type="module">`，同时还能使用 ESM import。

## 21. 回流和重绘有什么区别？`[S6][S8]`

### 我的回答

回流或布局是元素几何信息变化后重新计算位置和尺寸；重绘是外观变化但布局不一定改变，例如颜色变化。回流通常可能引发后续重绘，成本更高。

频繁交替读取 `clientHeight`、`getBoundingClientRect` 与写入样式，可能强制浏览器同步布局。我的滚动逻辑用 requestAnimationFrame 合并一帧内事件；进一步优化会集中读取、集中写入，并优先使用 transform/opacity 做动画。

## 22. 你真的实现了虚拟列表吗？底层应该怎么做？`[S5][S6][S12]`

### 我的回答

当前项目不应该声称已经实现严格虚拟列表。现在用 `v-show` 只显示活动视频附近三项，但其他节点仍然存在 DOM 中。

真正的定高虚拟列表会根据 scrollTop、容器高度和 itemHeight 计算 start/end，只渲染可视区加缓冲区的数据；外层保留总高度，渲染区通过 transform 偏移到正确位置。动态高度还要测量每项高度、维护前缀和并用二分查找定位起始下标，复杂度更高。

这种诚实表述比把 `v-show` 包装成虚拟列表更安全，也说明我知道下一步如何演进。

## 23. 如何证明一次前端性能优化真的有效？`[S3][S5][S6]`

### 我的回答

我会先确定指标和基线，再做单一变量修改并复测，而不是只凭“感觉更快”。加载性能可以看 LCP、资源体积、请求瀑布和接口时间；交互看 INP、长任务和 FPS；内存看堆快照和节点数量。

例如虚拟列表优化应该记录相同数据量下 DOM 节点数、滚动帧率、长任务时间和内存，而不是只说“页面不卡了”。压缩图片可以比较传输字节、解码时间和 LCP。测试环境、网络节流和数据规模要尽量一致。

## 24. 你的 Token 刷新怎么避免并发风暴？`[S4][S7]`

### 我的回答

多个接口同时 401 时，第一个请求创建 refresh Promise，其他请求等待同一个 Promise。成功后每个原请求携带新 Token 重试一次，失败则统一清理登录状态。

这叫 single-flight。还必须避免 refresh 接口自身再触发 refresh，限制重试次数，并考虑刷新过程中用户主动退出、旧请求晚返回等竞态。前端存在 Token 只用于 UI 判断，真正安全校验始终在后端。

## 25. 项目中的 Pinia 为什么不全部持久化？`[S7]`

### 我的回答

Store 是否持久化取决于数据的可靠来源和敏感性，而不是为了刷新后看起来不丢数据。登录 Token 需要刷新恢复，所以当前显式存储；通知列表、未读数和关注关系都可以从服务端恢复，盲目持久化可能先展示过期数据，还增加版本迁移成本。

Pinia 持久化插件底层通常也是把选定 state 序列化到 localStorage/sessionStorage。浏览器存储容量、过期、跨标签同步、安全和 schema 升级都要自行处理。

## 26. Composition API 有什么好处？`[S12]`

### 我的回答

它让代码按业务关注点组织，而不是把相关逻辑拆散到 data、computed、methods 和 lifecycle 中。复杂逻辑能提取成 composable，并自然获得 TypeScript 类型推导。

我的播放器状态、DOM Map、滚动 RAF、播放控制都在 `useVideoPlayer` 中；Feed 的三套分页状态在 `useVideoFeed`；跨页面共享的登录和通知则交给 Pinia。Composition API 不是把所有代码都塞进 setup，合理拆分才是价值。

# 五、B 级真题：纯前端岗位更常见，但要能接住

## 27. call、apply、bind 有什么区别？箭头函数能被修改 this 吗？`[S3][S4][S5]`

### 我的回答

三者都用于普通函数的 this 控制。call 立即调用并逐个传参，apply 立即调用并传参数数组，bind 返回一个绑定 this 的新函数，稍后调用。

箭头函数没有自己的 this，它从词法作用域捕获，因此 call/apply/bind 不能改变箭头函数的 this。我的 Vue Composition API 代码很少依赖 this，回调使用箭头函数主要是为了简洁和词法作用域。

## 28. `new` 一个对象发生什么？`[S4][S12]`

### 我的回答

简化过程是：创建新对象；把它的原型连接到构造函数的 prototype；用新对象作为 this 执行构造函数；如果构造函数显式返回对象则使用该对象，否则返回新对象。

现代业务代码更常使用 class 或工厂函数，但理解 new 有助于理解原型链和 instanceof。

## 29. 深拷贝怎样处理循环引用？`[S3][S4][S12]`

### 我的回答

递归深拷贝时使用 WeakMap 记录“源对象 → 已创建副本”。再次遇到同一个源对象直接返回记录的副本，避免无限递归，并保持共享引用关系。还要区分 Date、RegExp、Map、Set、数组、symbol key 和属性描述符。

实际业务优先考虑 `structuredClone` 是否满足需求，不轻易手写一个不完整的通用深拷贝。JSON 序列化会丢类型，也无法处理循环引用。

## 30. CSS 如何水平垂直居中？盒模型是什么？`[S3][S6][S8]`

### 我的回答

最直接的是 Flex：

```css
.container {
  display: flex;
  justify-content: center;
  align-items: center;
}
```

Grid 也可以用 `place-items: center`。具体方案要看元素是否定宽、是否脱离文档流和兼容要求。

盒模型由 content、padding、border、margin 组成。`content-box` 的 width 只算内容；`border-box` 的 width 包含 padding 与 border。项目全局使用 border-box，避免 `width: 100%` 再加 padding 后溢出。

## 31. 什么情况可能造成前端内存泄漏？`[S4]`

### 我的回答

常见原因是未移除的全局事件监听、未清理的定时器、未关闭的 SSE/WebSocket、仍被闭包或 Map 引用的 DOM、未 revoke 的 Object URL，以及第三方实例没有 destroy。

我的首页卸载时移除 keydown，AppShell 关闭 EventSource，发布页撤销预览 URL。排查时用 Memory 堆快照、Detached DOM Trees 和多次进入退出页面后的对象数量对比。

## 32. 从零搭建前端项目会先考虑什么？`[S1]`

### 我的回答

我先确认业务范围、浏览器兼容、是否需要 SSR/SEO、团队技术栈和部署方式，再确定 Vue 3 + TypeScript + Vite。随后建立路由、状态边界、API Client、环境变量、错误处理、目录规范、CSS 基线和鉴权流程。

工程层补 ESLint、格式化、单元测试、构建检查和 CI；安全层确定 Token 方案、CSP 与依赖治理；部署层确定 Nginx history fallback、API 代理、缓存与 SSE 配置。不能只运行脚手架就认为架构完成。

## 33. 哪些组件应该测试？`[S3]`

### 我的回答

优先测试业务风险高、分支多、容易回归的逻辑，而不是所有静态样式。我的优先级是 401 single-flight、Feed reset/append、上传并发不超过三、通知去重与已读计数、路由鉴权，以及 AsyncState 的 loading/error/empty/slot 行为。

纯展示组件可以少测；调用网络和 EventSource 的 Store 应 mock 外部依赖；少量 E2E 覆盖登录、发布、点赞和双用户实时通知。当前项目自动化测试尚未完全接入，我会如实说明。

## 34. 你如何使用 AI 编程工具？`[S9][S10]`

### 我的回答

我把 AI 当作加速分析和生成候选方案的工具，不把输出直接等同于正确代码。我会先明确接口契约和验收条件，让它处理样板代码、测试用例草稿或排查思路，然后自己阅读 diff、运行类型检查和测试，并通过 Network、数据库和日志验证完整链路。

涉及鉴权、并发、文件上传和数据删除时，我会重点检查安全边界、竞态和错误分支。面试中我能解释每段进入项目的代码，而不是只说“AI 生成的”。
