# 一、必须掌握：项目与 Vue 基础

## 1. 请介绍项目，并说一个真正的难点

### 先说人话

面试官不是想听一串技术名词，而是想确认三件事：项目解决什么问题、你具体做了什么、遇到困难时你如何设计和验证。

“难点”不能只说“代码很多”。一个合格难点通常包含：原始问题、方案选择、关键实现、异常情况和不足。

### 项目例子

FeedGo 是一个短视频系统。前端负责推荐流、关注、点赞、评论、通知和视频上传，后端负责接口、数据存储和消息处理。分片上传是合适的难点：大文件被切成多个小块，最多同时上传三块，失败只重传对应块；重新选择同一文件时，由后端告诉前端缺哪些块。

### 面试时这样答

> 我做的是 Go + Vue 3 的短视频 Feed 系统。前端使用 TypeScript、Pinia、Vue Router 和 Vite，后端使用 Go、MySQL、Redis 与 RabbitMQ。一个主要难点是大文件分片上传。前端先计算文件标识，把文件按 5 MiB 切片，询问后端已经收到哪些片，然后只上传缺失部分，并把并发数限制为三。这样单片失败不需要重传整个文件，也支持断点续传。当前不足是重试还可以增加指数退避，大文件哈希也可以放进 Web Worker，避免占用页面主线程。

## 2. Vue 2 和 Vue 3 有什么核心区别

### 先说人话

Vue 是帮助我们“用数据控制页面”的框架。Vue 3 是新一代版本。对于初学者，最重要的不是背所有内部变化，而是理解两点：Vue 3 更适合 TypeScript；Composition API 可以把同一功能的状态和方法放在一起。

Vue 2 主要通过 `Object.defineProperty` 监听对象已有属性。Vue 3 对普通响应式对象主要使用 `Proxy`，能统一拦截读取、修改、新增和删除属性。

### 项目例子

FeedGo 把 Feed 逻辑放进 `useVideoFeed`，把播放器逻辑放进 `useVideoPlayer`。这比把变量放在 `data`、计算放在 `computed`、函数放在 `methods` 更容易按功能查找。

### 面试时这样答

> 我主要使用 Vue 3。对我最直接的变化是 Composition API，它让我按照业务功能组织代码，并把 Feed、播放器等逻辑提取成 composable。Vue 3 的响应式对象主要基于 Proxy，对新增和删除属性的处理比 Vue 2 的 `Object.defineProperty` 更自然，同时对 TypeScript 和 Tree Shaking 的支持也更好。我不会说 Vue 3 在所有场景都一定更快，因为旧项目是否升级还要考虑生态和迁移成本。

## 3. Vue 3 响应式是怎么实现的

### 先说人话

响应式就是：变量变化以后，使用这个变量的页面能够自动更新。

```ts
const count = ref(0)
count.value++
```

模板中显示 `count` 的地方会更新，不需要手动查找 DOM 改文字。

原理可以记成：**读取时登记，修改时通知**。组件渲染时读取了某个属性，Vue 就记下“这个组件依赖该属性”；属性被修改后，Vue 通知相关组件重新计算需要更新的 DOM。

### 项目例子

```ts
const loading = ref(false)
```

模板使用 `loading` 显示加载状态。请求开始时设为 `true`，结束时设为 `false`，Vue 自动切换页面内容。

### 面试时这样答

> Vue 3 响应式可以概括为读取时收集依赖、修改时触发更新。`reactive` 对象主要通过 Proxy 拦截属性读取和修改；渲染或 computed 读取属性时建立依赖关系，属性变化后调度相关更新。`ref` 把值包装在 `.value` 中，模板会自动解包。响应式是“状态变化驱动视图”，而 `v-model` 才是在此基础上把用户输入再写回状态。

## 4. computed 和 watch 有什么区别

### 先说人话

`computed` 用来“根据已有数据算出一个新值”，而 `watch` 用来“某个数据变化后做一件事”。

```ts
const fullName = computed(() => firstName.value + lastName.value)
```

`fullName` 只是计算结果，没有发请求、写存储等额外动作。

```ts
watch(keyword, () => loadSearchResult())
```

关键词变化后发送请求，这就是副作用：除了算出一个值，还影响了外部世界。

### 项目例子

表单能否提交由标题和加载状态算出，使用 `computed`；文件变化后创建视频预览 URL，需要调用浏览器 API，使用 `watch`。

### 面试时这样答

> computed 适合派生值，并且有缓存，依赖不变时重复读取不会重新计算。watch 适合数据变化后执行请求、写存储、控制播放器等副作用。能用 computed 表达的逻辑不应再用 watch 手动维护另一份状态，否则容易出现两份数据不一致。

## 5. Vue 生命周期怎么用

### 先说人话

组件也有“出生、出现在页面、更新、离开页面”的过程。生命周期钩子就是让我们在这些时机执行代码。

```text
setup 执行
   ↓
组件 DOM 创建完成：onMounted
   ↓
组件运行和更新
   ↓
准备删除：onBeforeUnmount
   ↓
删除完成：onUnmounted
```

### 项目例子

首页在 `onMounted` 中加载 Feed 和注册键盘事件；在 `onBeforeUnmount` 中移除监听、取消 RAF。否则组件虽然离开了，全局事件仍可能继续触发旧函数。

### 面试时这样答

> onMounted 在组件第一次挂载到页面后执行，适合访问模板 DOM、初始化播放器和注册浏览器事件。onBeforeUnmount 或 onUnmounted 用于移除监听、取消定时器、关闭连接和释放预览 URL。请求如果不依赖 DOM，也可以在 setup 中启动，并不是所有请求都必须放 mounted；关键是资源由谁创建，就由谁负责清理。

## 6. ref 和 reactive 有什么区别

### 先说人话

两者都能创建响应式数据。`ref` 像一个带 `.value` 的盒子，适合单个值；`reactive` 把整个对象变成响应式，适合表单。

```ts
const loading = ref(false)
loading.value = true

const form = reactive({ title: '', description: '' })
form.title = '新标题'
```

### 项目例子

当前视频可能不存在，所以使用：

```ts
const video = ref<Video | null>(null)
```

发布表单字段较多，所以使用 `reactive`。

### 面试时这样答

> ref 可以保存任意类型，脚本中通过 `.value` 访问，适合单个值和需要整体替换的数据；reactive 主要用于对象，可以直接修改属性，适合表单。直接解构 reactive 的普通属性可能失去响应式联系，所以我通常保留对象访问，或者使用 `toRefs`。DOM ref 初始为 null，是因为 setup 执行时元素还没有创建。

## 7. 组件有哪些通信方式

### 先说人话

组件通信就是“一个组件怎样把数据或事件告诉另一个组件”。

```text
父组件给子组件数据：props
子组件通知父组件：emit
父组件给子组件一块页面内容：slot
相隔很多层共享少量依赖：provide/inject
多个页面共享业务状态：Pinia
```

### 项目例子

评论抽屉接收当前视频 ID 使用 props；点击关闭时 emit 通知首页；通知列表和侧栏角标相隔较远，因此共享 Pinia Store。

### 面试时这样答

> 父传子使用 props，子通知父使用 emits，内容结构复用使用 slot；跨多层但范围明确时可以使用 provide/inject，跨页面共享业务状态使用 Pinia。我的评论抽屉使用 props 和 emits，通知列表、未读数和连接状态放在 Pinia。选择方式的原则是让数据来源清楚，而不是所有状态都放全局。

## 8. 为什么使用 Pinia，刷新后数据会不会丢

### 先说人话

Pinia 是多个组件共享数据的集中仓库。它默认仍然只是浏览器内存，刷新页面后 JavaScript 重新运行，Store 也会重新创建，所以数据会丢。

需要跨刷新保留的数据，必须另外写入 localStorage、Cookie，或者重新向后端请求。

### 项目例子

侧栏显示未读数，通知页显示通知列表，两者需要同一份状态，所以使用通知 Store。刷新后通知重新从后端加载，不把可能过期的通知列表永久保存到本地。

### 面试时这样答

> Pinia 用来管理多个不相邻组件共同使用的响应式状态。项目中 AppShell 管理通知连接，侧栏显示未读数，通知页显示列表，因此共享同一个 Store。Pinia 默认存在内存中，刷新会重新创建；需要恢复的 Token 当前显式写入 localStorage，通知数据则重新请求后端。持久化不是越多越好，因为本地数据可能过期，敏感 Token 还要考虑 XSS 风险。

## 9. hash 路由和 history 路由有什么区别

### 先说人话

SPA 切换页面时通常不重新下载整份 HTML，而是由前端替换组件。

Hash 地址类似：

```text
example.com/#/video/1
```

`#` 后面的内容不会作为普通服务器路径发送，部署简单。

History 地址类似：

```text
example.com/video/1
```

更自然，但用户刷新时，服务器必须把这个路径仍然交给 `index.html`，然后由 Vue Router 决定显示哪个组件。

### 面试时这样答

> Hash 模式的 URL 带 `#`，井号后的内容主要由浏览器前端处理，服务器配置简单；History 模式使用 History API，URL 更自然，但直接刷新 `/video/1` 时服务器必须回退到 `index.html`，否则会把它当真实文件路径并返回 404。项目使用 `createWebHistory()`，Nginx 通过 `try_files $uri $uri/ /index.html` 完成回退。

## 10. Vite 为什么开发启动快

### 先说人话

传统工具启动时可能先把大量文件合成几个大包，项目越大等待越久。Vite 开发阶段利用浏览器模块能力，浏览器访问哪个模块，开发服务器再处理哪个模块，所以启动更快。

生产环境不能把开发服务器直接上线，仍然要执行构建，把代码压缩、删除无用代码、拆包并给文件名加哈希。

### 面试时这样答

> Vite 开发阶段利用浏览器原生 ESM 按需提供模块，不需要启动前先把全部业务代码打成一个 bundle；依赖会预构建，HMR 也只更新相关模块。生产阶段仍要构建，进行 Tree Shaking、压缩、代码拆分和资源哈希。项目先用 `vue-tsc -b` 做类型检查，再由 Vite 输出 dist，最后交给 Nginx 托管。

## 11. JavaScript 事件循环怎么执行

### 先说人话

JavaScript 主线程一次只能做一件事。普通代码先按顺序执行；定时器、网络等需要等待的工作交给浏览器处理，完成后再排队。

当前同步代码结束后，先执行微任务，例如 `Promise.then` 和 `await` 后面的代码；再进入后续任务，例如 `setTimeout`。

```ts
console.log('A')
setTimeout(() => console.log('B'), 0)
Promise.resolve().then(() => console.log('C'))
console.log('D')
```

结果通常是：

```text
A D C B
```

### 面试时这样答

> JavaScript 同步代码先在调用栈中执行。当前任务结束并且调用栈清空后，事件循环先清空微任务队列，再进入后续任务，浏览器也可能在合适时机渲染。Promise 回调和 await 后续通常属于微任务，setTimeout 回调属于后续任务。因此 `setTimeout(..., 0)` 也不是立即执行。

## 12. Promise.all 一个失败，其他请求会停止吗

### 先说人话

`Promise.all` 表示“这些任务必须全部成功”。只要一个失败，`Promise.all` 的整体结果马上失败并进入 `catch`。但是其他已经启动的任务不会因此自动停下。

```text
请求 A：1 秒成功
请求 B：2 秒失败 → Promise.all 失败
请求 C：5 秒成功 → C 通常仍会继续运行
```

真正取消 fetch 需要 `AbortController`。如果希望等待所有任务结束并分别查看成功失败，使用 `Promise.allSettled`。

### 面试时这样答

> Promise.all 要求全部成功，一个输入 reject 后，外层 Promise 会立即 reject，但其他已经启动的异步任务默认不会自动取消。fetch 需要使用 AbortController 主动取消。项目同时加载通知列表和未读数，两者任何一个失败都把本次同步视为失败；如果业务允许部分成功，可以改用 allSettled。

## 13. 浏览器输入 URL 到页面显示发生了什么

### 先说人话

可以把过程理解为“找到服务器、建立安全连接、下载文件、把代码变成画面”。

```text
解析 URL
→ 查询 DNS，把域名变成服务器 IP
→ 建立 TCP 连接
→ HTTPS 进行 TLS 安全握手
→ 发送 HTTP 请求
→ 下载 HTML、CSS、JS
→ HTML 变成 DOM，CSS 变成样式规则
→ 计算位置、绘制像素
→ JS 启动 Vue 并请求业务数据
```

### 面试时这样答

> 浏览器先解析 URL、检查缓存并通过 DNS 找到服务器，然后建立 TCP 连接；HTTPS 还需要 TLS 握手。服务器返回 HTML 后，浏览器解析 HTML 创建 DOM，解析 CSS，计算布局并绘制页面，同时按规则加载和执行 JavaScript。我的项目由 Nginx 返回 Vue 静态文件并代理 `/api`，Vue 启动后安装 Pinia 和 Router，再请求 Feed 数据。

## 14. 什么是跨域，项目怎么解决

### 先说人话

一个地址的“源”由协议、主机、端口组成。三者有一个不同，就是不同源。

```text
http://localhost:5173
http://localhost:8080
```

端口不同，所以前端直接请求后端属于跨域。浏览器为了安全，不允许网页随便读取其他源的响应。后端可以用 CORS 响应头明确允许；也可以由 Vite 或 Nginx 代理，让浏览器始终请求同一个源。

### 面试时这样答

> 协议、主机和端口任一不同就属于不同源。浏览器同源策略限制脚本读取跨源响应，复杂请求可能先发送 OPTIONS 预检。开发环境由 Vite 把 `/api` 代理到 Go 后端，生产环境由 Nginx 做同源反向代理。代理解决请求路径和跨域问题，但不代替后端鉴权，CORS 也不是接口权限控制。

## 15. Cookie、localStorage、sessionStorage 有什么区别

### 先说人话

三者都由浏览器管理，但用途不同。

```text
Cookie：请求时可自动发给服务器，可设置 HttpOnly 等安全属性
localStorage：保存在浏览器站点存储中，关闭浏览器后通常仍在
sessionStorage：属于当前标签页会话，关闭标签页后通常清除
```

localStorage 和 sessionStorage 都能被同源 JavaScript 读取，所以发生 XSS 时都有被读取的风险。

### 面试时这样答

> Cookie 会按域和路径规则随请求发送，并能设置 HttpOnly、Secure 和 SameSite；localStorage 长期保留并可由 JavaScript 读取；sessionStorage 主要属于当前标签页会话。项目当前把 Token 放在 localStorage，开发方便但存在 XSS 风险。更稳妥的生产方案是让 Refresh Token 使用 HttpOnly Cookie，Access Token 短期保存在内存，并由后端最终判断 Token 是否有效。

# 三、项目深入：实时连接、请求和性能

## 16. SSE 和 WebSocket 怎么选，断线怎么办

### 先说人话

SSE 是服务器持续向浏览器单向推消息，适合通知和大模型流式输出；WebSocket 可以双方随时发消息，适合聊天、协作和游戏。

SSE 的 `EventSource` 通常会自动重连，但自动重连不等于自动补回断线期间的消息。WebSocket 断线后通常需要自己实现重连、心跳和重新订阅。

### 项目例子

FeedGo 通知只需要服务器推给浏览器，所以选择 SSE。通知先写数据库，再实时推送。重连后重新请求通知列表，并按通知 ID 去重，就能恢复漏掉的数据。

### 面试时这样答

> SSE 是基于 HTTP 的服务端单向文本流，EventSource 原生支持自动重连；WebSocket 是全双工，适合高频双向通信。通知只需要服务端推送，所以项目选择 SSE。断线恢复不能只依赖重连，我会在连接恢复后重新加载数据库中的通知和未读数，并按 ID 去重；更严格的方案可以让服务端发送事件 ID，并支持 Last-Event-ID 回放。

## 17. 服务器短时间推送很多次，页面卡顿怎么办

### 先说人话

问题通常不是“网速太快”，而是前端每收到一个小片段就修改响应式数据，导致 Vue 和浏览器频繁更新页面。

解决办法是先把数据放入普通队列，每一帧或每几十毫秒批量提交一次。大模型打字机效果还可以让网络继续快速接收，而页面按阅读速度逐步消费；积压太多时，每次多显示一些字符。

`requestAnimationFrame` 简称 RAF，表示在浏览器下一次绘制画面前执行一次回调。

### 面试时这样答

> 高频推送时我不会每个片段都更新响应式状态，而是先写入非响应式缓冲区，再使用 requestAnimationFrame 或短定时器批量提交 UI。流式文本可以把网络接收与展示速度分开：接收队列保证数据不丢，展示端按批消费，积压增大时提高批量。组件卸载时要取消 RAF、定时器和网络请求。

## 18. 连续发送多个请求，怎么只使用最新结果

### 先说人话

用户先点“美食”，马上又点“游戏”。美食请求可能更晚返回，从而把游戏结果覆盖掉。启动新请求不会自动取消旧请求。

解决方式有两种：用 `AbortController` 真正取消旧 fetch；或者给每次请求编号，旧编号返回时不更新页面。

```ts
const requestId = ++latestRequestId
const result = await search(keyword)
if (requestId !== latestRequestId) return
items.value = result.items
```

### 面试时这样答

> 我会使用 AbortController 或请求版本号。新查询开始前取消旧 fetch；如果底层任务不能取消，就为每次请求生成递增 ID，只有返回 ID 等于当前最新 ID 时才更新状态。这样可以防止旧请求晚回来覆盖新页面。

## 19. 浏览器缓存怎么工作

### 先说人话

缓存就是浏览器把下载过的文件保存在内存或磁盘，下次尽量复用。强缓存允许在有效期内直接使用本地文件；协商缓存会问服务器“旧文件还能用吗”，没变化时服务器返回 304。

带内容哈希的 JS/CSS，例如 `index-abc123.js`，内容变化后文件名也变化，适合长期缓存。`index.html` 是寻找最新 JS 的入口，应短缓存或每次验证。通知和私信是实时私人数据，通常不缓存。

### 面试时这样答

> 强缓存通过 Cache-Control 等响应头，让有效期内的资源直接使用本地副本；协商缓存通过 ETag 或 Last-Modified 向服务器确认，未变化时返回 304。`no-cache` 是使用前要验证，`no-store` 才是不保存。Vite 的哈希 JS/CSS 适合长期缓存，index.html 应短缓存或协商缓存，实时接口和 SSE 不应按静态资源方式长期缓存。

## 20. script 的 async 和 defer 有什么区别

### 先说人话

普通外部脚本是：

```html
<script src="/app.js"></script>
```

浏览器遇到它可能暂停 HTML 解析，先下载并执行脚本。

`async` 和 `defer` 都允许后台下载，但：

```text
async：谁先下载完谁先执行，可能打断 HTML，顺序不保证
defer：等 HTML 解析完成，再按文档顺序执行
```

### 面试时这样答

> 普通外部脚本可能阻塞 HTML 解析。async 和 defer 都能并行下载；async 下载完成后尽快执行，多个脚本顺序不保证，适合独立统计脚本；defer 等 HTML 解析完成后按文档顺序执行，适合依赖 DOM 或有依赖关系的业务脚本。Vite 入口使用 `type="module"`，模块脚本默认具有类似 defer 的行为。

## 21. 回流和重绘有什么区别

### 先说人话

浏览器渲染页面时，需要计算元素的位置和大小，再把颜色、文字等画成像素。

修改宽高、间距或增删元素后，需要重新计算布局，这叫回流或 Layout。只改颜色等外观，通常不需要重新计算位置，但需要重新画，这叫重绘或 Paint。

```text
修改 width：通常回流 + 重绘
修改 background-color：通常重绘
动画使用 transform/opacity：通常更容易交给合成阶段处理
```

### 面试时这样答

> 回流是元素尺寸、位置或结构变化后重新计算布局；重绘是布局不一定变化，但颜色等外观需要重新绘制。回流通常还会带来重绘，成本更高。频繁交替读取尺寸和修改样式可能造成布局抖动，所以我会集中读取、集中写入，并用 requestAnimationFrame 合并一帧内的滚动更新，动画优先考虑 transform 和 opacity。

## 22. 什么是真正的虚拟列表

### 先说人话

如果有一万条数据，普通 `v-for` 会创建大量 DOM，但屏幕一次可能只看见十条。虚拟列表保留全部数据，却只创建可视区域附近的少量 DOM，并用占位高度模拟完整滚动条。

```text
数据：10000 条
页面真实 DOM：约 20 条
滚动以后：替换这 20 条代表的数据
```

`v-show` 只是把元素隐藏，DOM 仍然存在，所以不等于虚拟列表。

### 面试时这样答

> 当前项目只显示活动视频附近内容，但不能把单纯的 v-show 说成严格虚拟列表，因为隐藏节点仍在 DOM。真正的定高虚拟列表根据 scrollTop、容器高度和每项高度计算 start/end，只渲染可视区加缓冲区，外层保留总高度，内容区通过 transform 移动到正确位置。动态高度还需要测量和缓存每项高度，复杂度更高。

## 23. 如何证明性能优化有效

### 先说人话

“感觉更快”不是证据。先选指标，在相同设备、数据、网络、窗口和缓存条件下，测优化前和优化后，并且多测几次。

虚拟列表应该比较 DOM 数量、首次渲染时间、滚动掉帧、长任务和内存；图片优化应该比较传输体积、下载时间和 LCP。

### 面试时这样答

> 我会先建立基线，再做单一变量修改并在相同环境复测。比如虚拟列表要比较相同数据量下的 DOM 节点数、首次渲染时间、主线程长任务、滚动帧率和内存，而不是只说页面不卡了。至少运行多次并比较中位数或 P75，最后还要验证滚动位置、功能和可访问性没有退化；上线后再观察真实用户的 LCP、INP、CLS 和错误率。

## 24. Token 刷新怎么避免并发风暴

### 先说人话

页面可能同时有五个请求，都发现 Access Token 过期。如果每个请求都各自刷新一次，就会同时发送五次刷新请求，甚至相互覆盖。

正确做法是：第一个 401 创建一个共享的刷新 Promise，其他请求等待同一个 Promise。刷新成功后，各自带新 Token 重试一次。

### 面试时这样答

> 多个请求同时 401 时，第一个请求创建 refreshPromise，其他请求复用并等待它，这种合并相同并发工作的方式叫 single-flight。刷新成功后原请求各自重试一次，失败则统一清理登录状态。还要排除 refresh 接口自身、防止无限重试，并处理刷新过程中用户退出等竞态。

## 25. Pinia 为什么不全部持久化

### 先说人话

持久化通常就是把 Store 序列化到 localStorage。它能让刷新后还有数据，但本地数据可能过期、结构可能升级，敏感数据还存在安全风险。

后端数据库已经是通知和关注关系的可靠来源，所以刷新后重新请求比长期保存旧副本更稳妥。

### 面试时这样答

> Store 是否持久化取决于数据来源、时效性和敏感性。Token 当前为了刷新恢复而显式存储；通知列表、未读数和关注关系都能从后端恢复，盲目持久化会先展示过期数据，还要处理过期时间、跨标签同步和数据结构升级。持久化不是越多越好。

## 26. Composition API 有什么好处

### 先说人话

它让同一个功能的变量、计算、函数和生命周期放在一起，并能提取为可复用函数。重点不是“都写进 setup”，而是按业务拆分。

### 面试时这样答

> Composition API 让我按照业务关注点组织代码，而不是把一个功能拆散到 data、computed、methods 和生命周期中。项目把播放器逻辑提取到 `useVideoPlayer`，Feed 状态提取到 `useVideoFeed`，跨页面共享状态交给 Pinia。这样更容易复用、测试和获得 TypeScript 类型推导。

# 四、扩展题：理解即可，但要能说清楚

## 27. call、apply、bind 有什么区别

### 先说人话

普通函数中的 `this` 表示函数执行时关联的对象。三者都能指定普通函数的 `this`：

```text
call：立即执行，参数一个个传
apply：立即执行，参数用数组传
bind：先返回一个绑定后的新函数，以后再执行
```

箭头函数没有自己的 `this`，它使用外层作用域的 `this`，所以这三个方法不能改变箭头函数的 `this`。

### 面试时这样答

> call 和 apply 都会立即调用函数，区别是 call 逐个传参，apply 接收参数数组；bind 不立即执行，而是返回绑定 this 的新函数。箭头函数使用词法 this，call、apply、bind 不能改变它。Vue 3 Composition API 通常很少依赖组件 this。

## 28. new 一个对象发生什么

### 先说人话

```js
const user = new User('小明')
```

可以简化理解为：创建一个空对象，让它能访问 `User.prototype` 上的方法，用这个对象作为 `this` 执行 `User`，最后返回它。

### 面试时这样答

> new 会创建一个新对象，把新对象的原型连接到构造函数的 prototype，再以新对象为 this 执行构造函数。如果构造函数显式返回一个对象，就使用该对象，否则返回新创建的对象。理解这个过程有助于理解原型链和 instanceof。

## 29. 深拷贝怎样处理循环引用

### 先说人话

循环引用就是对象最终又指回自己：

```js
const user: any = { name: '小明' }
user.self = user
```

普通递归会永远复制下去。解决方法是用 `WeakMap` 记录“这个源对象已经复制成哪个新对象”，再次遇到时直接返回已有副本。

### 面试时这样答

> 递归深拷贝时使用 WeakMap 保存源对象到副本的映射。第一次遇到对象先创建副本并登记，再复制属性；再次遇到同一源对象时直接返回记录的副本，从而避免无限递归并保持引用关系。实际业务优先判断 `structuredClone` 是否满足需求，JSON 序列化不能处理循环引用，也会丢失部分类型。

## 30. CSS 居中和盒模型是什么

### 先说人话

最常用的水平垂直居中：

```css
.container {
  display: grid;
  place-items: center;
}
```

或者 Flex：

```css
.container {
  display: flex;
  justify-content: center;
  align-items: center;
}
```

一个元素的盒子由内容、内边距、边框和外边距组成。`border-box` 让设置的宽高包含 padding 和 border，更容易计算。

### 面试时这样答

> 居中可以使用 Flex 的 `justify-content: center` 和 `align-items: center`，Grid 也可使用 `place-items: center`。盒模型由 content、padding、border 和 margin 组成；默认 content-box 的 width 只计算内容，而 border-box 的 width 包含 padding 与 border。项目全局使用 border-box，减少 `width: 100%` 加 padding 后溢出的问题。

## 31. 什么情况会造成前端内存泄漏

### 先说人话

组件已经不用了，但某些引用仍然抓着它或其资源，垃圾回收器无法释放，这就是内存泄漏。

常见原因：全局事件没移除、定时器没停止、SSE/WebSocket 没关闭、DOM 仍被 Map 引用、视频预览 URL 没释放。

### 面试时这样答

> 常见泄漏来源包括未移除的 window 事件、未清理的定时器和 RAF、未关闭的 SSE/WebSocket、仍被闭包或 Map 引用的 DOM、未 revoke 的 Object URL，以及第三方实例没有 destroy。我的组件在卸载时做对应清理；排查时会多次进入退出页面，使用 Memory 堆快照和 Detached DOM Trees 比较对象是否持续增长。

## 32. 从零搭建前端项目先考虑什么

### 先说人话

不要一上来只运行脚手架。先确认产品要做什么、支持哪些浏览器、是否需要搜索引擎收录、如何登录、如何部署，再选技术。

### 面试时这样答

> 我先确认业务范围、浏览器兼容、是否需要 SSR/SEO、团队技术栈和部署方式，再确定 Vue 3、TypeScript 和 Vite。然后建立路由、状态边界、请求封装、环境变量、错误处理、CSS 基线和鉴权流程，再补 ESLint、测试和 CI。部署层还要考虑 Nginx History 回退、API 代理、缓存和 SSE 配置。

## 33. 哪些组件应该测试

### 先说人话

不是每个静态标题都要写复杂测试。优先测试“出错损失大、分支多、以后容易改坏”的逻辑。

### 项目例子

FeedGo 优先测试：多个 401 只刷新一次 Token、Feed 重置和追加、上传并发不超过三、通知 ID 去重、路由鉴权、加载/错误/空状态切换。

### 面试时这样答

> 我会按业务风险安排测试。优先覆盖 401 single-flight、Feed 分页、上传并发、通知去重、路由鉴权和 AsyncState 多状态；纯展示组件可以少测。网络和 EventSource 在单元测试中 mock，再用少量 E2E 覆盖登录、发布、点赞和实时通知完整链路。没有完成的自动化测试我会如实说明，而不是声称已经覆盖。

## 34. 如何使用 AI 编程工具

### 先说人话

AI 可以生成候选代码，但它不知道项目所有约束，也可能写出看似合理但实际错误的代码。使用 AI 的能力不在于复制得快，而在于能否定义问题、检查差异和验证结果。

### 面试时这样答

> 我把 AI 当作分析和生成候选方案的工具，不把输出直接当成正确代码。我先明确接口契约和验收条件，让它辅助生成样板代码、测试草稿或排查思路，然后自己阅读 diff，运行类型检查和测试，并通过浏览器 Network、后端日志和数据库验证完整链路。鉴权、并发、上传和删除操作会重点检查安全边界、竞态与失败分支，进入项目的代码我都要能解释。

# 七、文中术语随手查

| 术语 | 人话解释 |
| --- | --- |
| API | 前端和后端约定的通信入口，例如 `/api/videos`。 |
| DOM | 浏览器把 HTML 转换成的对象树，JavaScript 和 Vue 最终通过它修改页面。 |
| 响应式 | 数据变化后，使用该数据的页面能够自动更新。 |
| Proxy | JavaScript 提供的代理对象，能拦截对象属性的读取、修改、新增和删除。 |
| Composition API | Vue 3 按功能组织状态和函数的一套写法，例如 `ref`、`computed`、`onMounted`。 |
| composable | 可复用的 Vue 组合函数，通常以 `use` 开头，例如 `useVideoFeed`。 |
| SPA | 单页应用；首次加载入口 HTML，之后主要由前端路由切换组件。 |
| SSR | 服务端先生成 HTML，常用于首屏速度或搜索引擎收录要求较高的页面。 |
| SEO | 让搜索引擎更容易理解和收录页面。 |
| ESM | JavaScript 官方模块系统，使用 `import` 和 `export`。 |
| bundle | 构建工具把多个模块组合、优化后得到的代码包。 |
| HMR | 热模块替换；开发时只更新修改过的模块，不刷新整个页面。 |
| Tree Shaking | 构建时删除没有被使用的导出代码，减小生产包。 |
| 资源哈希 | 根据文件内容生成文件名片段；内容变化后 URL 也变化。 |
| DNS | 把域名查询成服务器 IP 地址的系统。 |
| TCP | 浏览器与服务器之间建立可靠数据传输连接的网络协议。 |
| TLS | HTTPS 使用的加密和身份验证协议。 |
| CORS | 后端通过响应头告诉浏览器，哪些其他来源可以读取响应。 |
| OPTIONS 预检 | 浏览器在部分跨域请求前先询问后端是否允许该方法和请求头。 |
| XSS | 攻击者让恶意 JavaScript 在可信网站中执行。 |
| CSRF | 利用用户已有登录状态，诱导浏览器向目标网站发送非本人意愿的请求。 |
| RAF / rAF | `requestAnimationFrame`，在浏览器下一次绘制前执行回调。 |
| 回流 / Layout | 页面尺寸或位置变化后，浏览器重新计算布局。 |
| 重绘 / Paint | 页面外观变化后，浏览器重新绘制像素。 |
| 虚拟列表 | 数据很多，但 DOM 只保留当前屏幕附近的少量列表项。 |
| LCP | 页面主要大块内容显示出来所花的时间。 |
| INP | 用户点击或输入后，页面给出下一次视觉反馈的延迟。 |
| CLS | 页面加载过程中元素意外跳动的累计程度。 |
| FPS | 每秒显示的画面帧数；稳定高帧率通常意味着动画更流畅。 |
| Long Task | 主线程执行时间超过约 50ms 的长任务，可能阻塞交互和渲染。 |
| P75 | 75% 的用户数据不超过这个值，比只看平均数更能反映多数用户体验。 |
| single-flight | 多个相同并发操作只真正执行一次，其他调用等待同一结果。 |
| WeakMap | 使用对象作为键的弱引用映射，常用于记录深拷贝中已处理的对象。 |
| `structuredClone` | 浏览器提供的结构化深拷贝方法，能处理循环引用和多种内置类型。 |
| CI | 提交代码后自动执行构建、类型检查和测试的流程。 |
| E2E | 端到端测试，从用户操作页面开始验证完整前后端链路。 |
| Mock | 测试时用可控的假实现替代网络、时间或第三方服务。 |
| CSP | 内容安全策略，用响应头限制页面允许加载和执行的脚本来源。 |
| 幂等 | 同一操作重复执行，最终结果仍与执行一次一致。 |
| 竞态 | 多个异步任务完成顺序不确定，导致旧结果覆盖新结果等问题。 |
