# FeedGo 前端 UI 五天重构计划

> 版本：v2.0（五天 MVP）  
> 开始日期：2026-10-16  
> 完成日期：2026-10-20  
> 参考产品：抖音网页版的沉浸式视频布局、导航层级和互动方式  
> 原则：只借鉴交互与布局，不复制抖音商标、素材和业务文案

> 交付平台：桌面 Web。当前阶段不开发 Android、iOS、小程序或手机专用导航；窄窗口仅做基础 Web 适配。

## 1. 五天目标

在不修改现有 Go 后端接口的前提下，将当前前端集中改造成一个可以用于项目展示的短视频 MVP。

本轮只重点交付：

1. 精选页及分类视频浏览。
2. 推荐主页。
3. 关注 Feed。
4. 视频点赞。
5. 视频评论。
6. 通知列表和实时通知。
7. 上述功能所必需的登录页面。
8. 分享链接所必需的最小视频详情页。

本轮不追求把所有现有页面全部重新设计，而是确保“精选发现—沉浸浏览—关注—点赞—评论—收到通知”这条核心链路完整、统一、可演示。

## 2. 页面范围

### 2.1 本轮重点重构

| 页面/模块 | 路由 | 本轮内容 |
| --- | --- | --- |
| 精选页 | `/jingxuan` | 顶部分类栏、多列视频卡片、分类切换、加载和空状态 |
| 推荐主页 | `/` | 沉浸式视频流、上下切换、自动播放、点赞、评论、关注、分享 |
| 关注 Feed | `/` 内的“关注”标签 | 展示已关注作者的视频；未登录时显示登录引导 |
| 通知页 | `/notifications` | 通知列表、未读状态、全部已读、SSE 实时通知和断线恢复 |
| 登录页 | `/account` | 登录、错误提示、登录后返回原页面 |
| 视频详情 | `/video/:id` | 分享链接落地、视频播放、点赞、评论、关注 |
| 评论抽屉 | 首页和详情页内 | 评论加载、发布、删除、错误重试 |

### 2.2 继续保留功能，但不在五天内重做 UI

- 注册和修改密码。
- 视频发布和分片上传。
- 用户主页。
- 私信。
- 设置。
- 热榜。

这些路由和已有代码不删除，避免破坏项目功能；只从本轮主导航中弱化或收进“更多”入口。

### 2.3 本轮明确不做

- 直播、商城、充值、音乐库、短剧、放映厅。
- 评论回复和评论点赞，因为当前后端没有相应接口。
- “我点赞过的视频”独立页面，因为当前接口只有视频点赞状态和点赞排行，没有查询当前用户全部点赞视频的接口。
- 精选卡片的视频时长角标，因为当前 Feed 返回结构没有视频时长字段；本轮不为显示一个角标批量加载所有视频元数据。
- 对抖音 Logo、品牌字体、图标和视频素材的复制。
- 全站所有旧页面的像素级统一。

## 3. 核心用户链路

```text
打开精选页并选择内容分类
  ↓
点击卡片进入视频详情，或者进入推荐主页
  ↓
浏览推荐视频并自动播放
  ↓
点赞 / 打开评论 / 关注作者
  ↓
未登录 → 跳转登录 → 登录成功返回原位置
  ↓
切换到关注 Feed 查看已关注作者视频
  ↓
进入通知页查看点赞、评论、关注通知
```

五天内的所有任务都围绕这条链路服务，不为非核心页面增加新功能。

## 4. 五天需求清单

### 第 1 天：设计系统与应用骨架

**完成日期：2026-10-16**

**实施状态：已完成（2026-10-16）**

- 已建立统一暗色设计令牌，并完成持久化 `AppShell`、桌面侧栏和顶部操作栏。
- 已接入 `@lucide/vue` SVG 图标，推荐页和详情页的核心互动图标已替换。
- 已新增 `/jingxuan` 路由及第一天页面骨架；真实分类数据和视频网格按第 2 天计划接入。
- 已通过 TypeScript 与生产构建检查；1280×720 浏览器实测无横向滚动且只有一个根布局。
- 1024×768、1440×900、1920×1080 的完整三视口回归将在第 5 天统一执行并记录。

#### 任务内容

- 建立 FeedGo 自有暗色设计令牌：背景、表面层、文字、强调色、边框、阴影、圆角、间距和动效。
- 接入统一 SVG 图标，替换点赞、评论、分享、播放、音量等 emoji 图标。
- 将 `AppShell` 调整为持久化根布局，页面通过嵌套 `RouterView` 切换。
- 桌面端采用固定左侧导航和顶部操作栏。
- 桌面端保留左侧导航；窄窗口将侧栏折叠为图标栏，不增加移动底栏。
- 主导航只突出：精选、推荐/关注、通知、我的/登录；其他功能放入更多入口。

#### 验收标准

- 路由切换时 `AppShell` 不被重新创建。
- 普通路由切换不会让通知 SSE 重复断开和连接。
- 页面中不再使用 emoji 作为主要功能图标。
- 当前导航项具有明确选中状态和 `aria-current`。
- 1440px 及以上显示完整侧栏，1024px 左右允许折叠为图标侧栏。
- 1024×768、1440×900、1920×1080 三组桌面视口无内容遮挡和横向滚动。

### 第 2 天：精选页和分类浏览

**完成日期：2026-10-17**

#### 任务内容

- 新增 `/jingxuan` 路由和 `JingxuanView` 页面。
- 采用“顶部可横向滚动分类栏 + 响应式多列视频网格”。
- 分类首期包含：全部、公开课、游戏、二次元、音乐、影视、美食、知识、生活 Vlog、体育、旅行、亲子、动物、汽车、美妆穿搭。
- “全部”复用现有热门/最新 Feed；具体分类调用已有 `/feed/listByTag`，按视频标题或描述中的真实 `#标签` 查询。
- 在前端 `feed.ts` 补充类型安全的 `listByTag` 请求方法。
- 视频卡片显示封面、标题、作者、点赞量和发布时间；点击进入 `/video/:id`。
- 分类切换时取消使用旧结果，显示骨架屏；无对应标签视频时显示真实空状态。
- “全部”支持继续加载；分类结果遵循当前接口最多 50 条、暂不分页的限制。

#### 验收标准

- `/jingxuan` 可以直接访问和刷新，Nginx 不返回 404。
- 桌面端根据宽度显示 3～5 列，窄窗口显示 2～3 列；没有横向页面滚动。
- 分类栏在页面滚动时保持可见；窗口不足以容纳全部分类时允许横向滚动并隐藏原生滚动条。
- 点击“美食”等分类时，实际请求 `/feed/listByTag`，不能只在浏览器中对当前列表做假筛选。
- 快速切换分类时，较早返回的请求不能覆盖当前分类结果。
- 卡片封面采用固定宽高比，不因图片加载造成明显布局跳动。
- 加载、空数据、错误重试和无更多数据都有独立状态。
- 点击视频卡片可以进入对应详情页，返回后保留已选分类；尽量恢复原滚动位置。

### 第 3 天：推荐、关注、点赞、评论和详情

**完成日期：2026-10-18**

#### 任务内容

- 重构首页视频舞台，突出当前视频，弱化无关界面元素。
- 重构视频信息层：作者、标题、描述、发布时间。
- 重构右侧互动栏：头像/关注、点赞、评论、分享。
- 使用可见性监听或等价机制管理当前视频。
- 当前视频自动播放，离屏视频自动暂停，只预加载相邻视频。
- 保留滚轮、方向键切换和 `M` 静音，但不常驻显示开发者式快捷键提示。
- 完善首页加载、空数据、错误重试和没有更多内容状态。
- 在首页提供“推荐”和“关注”两个清晰标签。
- 关注 Feed 继续调用现有 `listByFollowing` 接口。
- 点赞按钮调用现有点赞接口，并加入加载锁、防重复点击和失败回滚。
- 关注按钮调用现有关注接口，并同步 Pinia 社交状态。
- 重构评论抽屉：桌面从右侧展开；窄窗口允许增加抽屉宽度，但不制作手机底部抽屉。
- 评论支持加载、发布、删除、空状态、错误状态和重新加载。
- 完成最小视频详情页，让复制分享链接后可以打开对应视频。

#### 验收标准

- 每屏只突出一个视频，同一时间最多只有一个视频播放。
- 视频离开可视区后立即暂停；默认静音自动播放，用户主动操作后可以开启声音。
- 单击视频可以暂停/继续；上下滚动和方向键可以切换视频。
- 视频加载失败时显示封面、错误信息和重试按钮，而不是只有黑屏。
- Feed 加载下一页时不会发出重复并发请求。
- 未登录用户进入关注 Feed 时看到明确登录按钮，而不是空白页。
- 点赞成功后图标和数量立即更新；请求失败时恢复原状态并提示原因。
- 快速连续点击不会产生多个相同点赞请求。
- 关注状态在首页和详情页保持一致。
- 评论抽屉可以通过关闭按钮、遮罩和 `Esc` 关闭。
- 空白评论不可提交；提交期间按钮不可重复点击。
- 用户只能看到自己评论的删除入口。
- 分享按钮能够复制 `/video/:id` 链接，并显示成功或失败提示。

### 第 4 天：通知、登录与响应式

**完成日期：2026-10-19**

#### 任务内容

- 重构通知页，将点赞、评论、关注、提及显示为不同通知样式。
- 展示未读角标、单条已读和全部已读状态。
- 保留 Pinia 中的 EventSource，并完善断线状态与重连后的数据校准。
- SSE 收到新通知后按照服务端通知 ID 去重。
- 重构最小登录页，统一表单样式和错误反馈。
- 未登录用户触发点赞、评论、关注、通知时，跳转登录并保存原地址。
- 登录成功后返回原页面。
- 完成常规桌面、窄屏桌面和大屏桌面三种 Web 视口适配。

#### 验收标准

- 新通知到达时无需刷新页面即可显示，并更新未读数。
- 重复 SSE 消息不会在通知列表中出现两次。
- SSE 重连后重新请求通知列表和未读数，减少断线期间漏消息的影响。
- 通知连接失败不会阻止用户查看已经加载的通知。
- 未读通知具有清晰但不过度刺眼的视觉状态。
- 未登录访问 `/notifications` 会跳转 `/account`，登录后自动返回 `/notifications`。
- 1024×768、1440×900、1920×1080 三组桌面视口没有内容遮挡和横向溢出。

## 6. 精简后的组件结构

```text
App.vue
└─ AppShell（路由切换时保持）
   ├─ DesktopSidebar
   ├─ TopBar
   ├─ CollapsibleSidebar
   ├─ RouterView
   │  ├─ JingxuanView
   │  │  ├─ CategoryTabs
   │  │  └─ CuratedVideoGrid
   │  ├─ HomeView
   │  │  └─ FeedViewport
   │  │     ├─ VideoPlayer
   │  │     ├─ VideoMeta
   │  │     └─ ActionRail
   │  ├─ VideoDetailView
   │  ├─ NotificationsView
   │  └─ AccountView
   ├─ CommentDrawer
   └─ Toaster
```

状态划分：

- 页面内部：当前视频索引、播放状态、评论抽屉、输入内容。
- Pinia：Token、当前用户、关注关系、通知列表、未读数、EventSource、Toast。
- URL：当前页面、视频 ID、登录后的返回地址。
- 服务端：Feed、点赞、评论、关注和通知的最终数据。

## 7. 五天版视觉要求

- 使用 FeedGo 原创文字标识。
- 近黑背景配合 2～3 层深灰表面，避免整个页面糊成纯黑。
- 采用 FeedGo 自有珊瑚红作为主强调色，不照搬抖音品牌标识。
- 精选页强调“一屏看到多条内容”，使用封面网格；推荐页强调“一次只消费一条内容”，使用沉浸式播放器，两者不能共用同一种页面布局。
- 视频是首页最大视觉元素，导航和按钮不能抢夺注意力。
- 大屏桌面使用完整侧栏，窄屏桌面使用图标侧栏；本期不设计移动底栏。
- 所有按钮必须具备默认、悬停、按下、禁用、加载和键盘焦点状态。
- 动效控制在 120～280ms，并支持 `prefers-reduced-motion`。
